# V47.15 — additive warehouse remainder

## Problem

A receipt item could initially be confirmed as `Обов'язковий` or `Дозамовлення`, then workers could later discover that some quantity still remains for the ordinary warehouse flow. The old only-safe path was unconfirm -> reroute -> confirm, which could delete/recreate supplement artifacts and re-send notifications.

## Changes

- Added `POST /receipts/:id/items/:itemId/add-warehouse-remainder`.
- It is allowed only for confirmed current-routing regular items with `warehouse=false` and primary route mandatory/supplement.
- It only flips warehouse false->true and keeps the item confirmed.
- No supplement offer/request/notification code is called.
- Double tap/retry is idempotent with no repeated side effects.
- Supplement-only reuses its existing hidden Product and enables ordinary warehouse flow.
- Mandatory-only creates a warehouse Product and converts the existing standalone ShopProduct in place to a mirror, preserving the ShopProduct id and avoiding a duplicate card.
- Existing shop-owned ProductVector ownership is migrated to the warehouse Product when possible.
- UI exposes `+ Залишок → На склад` under the confirmed photo preparation card.

## Visual sorting scope correction

Earlier notes suggesting Block/Picking integration are superseded. Visual sorting must be presentation-only for seller `Товари -> Товари` (`MiniAppPage -> SellerCatalogView`) and must not modify Block, PickingTask, warehouse pages, sessions, eligibility, Orders, or categories.
