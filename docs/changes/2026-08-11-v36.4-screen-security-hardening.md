# v36.4 — Picking screen + security/integrity hardening

Date: 2026-08-11

## Picking UI
- Server-authoritative 24h `upcoming_preflight` now accepts both terminal `completed` and empty `idle` cycles.
- Client renders loading until the selected group's authoritative snapshot resolves.
- Late responses from a previously selected group are ignored across session/supplement/task flows.
- Screen priority moved into pure tested `derivePickingScreenKey()` state machine.
- Removed duplicate client-side 24h presentation calculator.

## Session purity
- Read-only status/presentation paths use `findCurrentSessionId` instead of materialising empty sessions.
- `GET /picking/session-status` no longer creates an `OrderingSession`.

## Security
- `/api/warehouse-test` requires explicit non-production opt-in plus admin auth; never public.
- Production CORS fails closed.
- Health/maintenance/provider error payloads expose less implementation detail to non-staff callers.
- Seller-facing Vision Search errors no longer disclose raw Gemini/Atlas details.
- Vercel baseline security headers added; production source maps stay off.
- Accidental secret env artifact excluded from release; rotate its credentials externally.

## Integrity / retention
- Order detach cleanup can only delete PickingTasks that actually contained that Order.
- Completed OrderingSession freezes `finalSummary`, preserving history after 90-day PickingTask retention.
- Reopen clears frozen summary and recomputes it on next completion.

## Multi-instance
- Repeating ordering/supplement/retention schedulers run behind shared leader lock; with Redis, one Render instance wins each tick.

## Verification additions
- live `security_boundaries`
- live `final_summary_retention`
- `test:live:security*`
- `test:live:race*`
- hardening contract/unit suite
