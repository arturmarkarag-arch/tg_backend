# V47.16 — supplement batches, incoming semantics, preparation footer

Date: 2026-08-15

## Why

Three regressions/UX issues were addressed together:

1. supplement-only technical `Product` rows were incorrectly visible in the
   warehouse `Надходження` placement queue;
2. confirming many supplement items could produce one Telegram notification per
   item;
3. photo preparation had scattered actions and Save did not clearly represent
   whether anything had actually changed.

## Incoming placement queue

`GET /api/blocks/incoming/products` and the matching nav badge now exclude
`orderingEnabled=false`.

This preserves the technical `Product` used by supplement requests/picking while
removing supplement-only goods from the physical "put this into a Block" queue.
`Дозамовлення + На склад` remains visible because its warehouse product has
`orderingEnabled=true`.

Client confirm/unconfirm/reroute consequences invalidate incoming/product/badge
queries, and `incoming_updated` also reconciles the nav badge.

## Batch-managed supplement publication

Current per-item supplement rows use:

- `supplementBatchVersion=1`;
- `supplementPublishRequestedAt`.

Confirm only makes the item ready. It does not create an offer or send Telegram.
The photo view groups ready items by delivery group and exposes one batch action.

`POST /receipts/supplement-batches/:deliveryGroupId/publish` stamps the whole
ready group atomically under a group lock. If ordinary ordering is closed, offers
are bulk-upserted and one notification call handles the group. If ordinary
ordering is still open, the durable publication request waits for the scheduler.

The scheduler reconciles pending receipts before its normal `findDueReminders`
notification pass. It intentionally does not notify from reconciliation itself;
this lets all open/unnotified offers from the same delivery group be claimed and
announced together, including retry/partial-repair cases.

Legacy batch version 0 remains migration-free and keeps the old behaviour.

## Photo preparation actions

Stage-2 form is now controlled by one footer:

- `Закрити`;
- `Зберегти`;
- `Підтвердити`.

`Зберегти` is disabled when there are no unsaved changes. Dirty state includes:

- price;
- quantity per package;
- price label position;
- package label position;
- every photo-comment id/text/position.

Therefore dragging a label on the photo is a real unsaved change and enables
Save. Closing with dirty state requires confirmation.

## Non-goals

No change was made to seller visual sorting, Blocks ordering, PickingTask,
positionIndex, session ordering, or product categorisation.
