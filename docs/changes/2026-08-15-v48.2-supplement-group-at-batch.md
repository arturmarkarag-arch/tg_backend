# V48.2 — supplement delivery group selected at batch publication

## Server

- Current regular receipt supplement items may be confirmed without `routing.supplementDeliveryGroupId`.
- `supplementBatchVersion=2` denotes current unassigned batch-managed rows; v1 remains compatible for historical per-item group rows.
- Pending batch API returns:
  - `readyCount` for confirmed/completed unassigned supplement items;
  - delivery-group `targets` for the one batch-level selection;
  - legacy grouped rows separately for rollout compatibility.
- Batch publication atomically assigns the selected delivery group to all currently ready unassigned items and claims publication with `supplementPublishRequestedAt`.
- Global `supplement-batch:publish` lock prevents two workers from assigning the same unassigned pool to different groups concurrently.
- Offer creation remains impossible before group assignment; one grouped Telegram notification is sent only after the full immediate batch is created.
- Deferred batches keep the selected group and open automatically after ordinary ordering closes.
- V48.1 seller visual ordering is unchanged.

- server syntax checks and previous receipt/core/visual-order static contracts pass.
